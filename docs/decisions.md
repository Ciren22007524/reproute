# 決策紀錄

已經做過的決定與原因。要推翻某個決定時，在這裡新增一筆，說明改變的原因，不要直接刪掉舊的。

| 日期       | 決定                                                                        | 原因                                                                                                | 不選的方案                         |
| ---------- | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ---------------------------------- |
| 2026-10-14 | 自己做，不直接用現成 App                                                    | 現成產品（Fitbod 等）沒有「依現場器材狀況重排整堂課」；個人使用、可依自己的健身房與訓練方式設計     | Fitbod、Hevy 等訂閱                |
| 2026-10-14 | 健身房器材自己清點，不抓健身工廠的資料                                      | 健身工廠沒有公開器材清單與即時狀態；爬會員 App 違反條款                                             | 爬取官方 App 或網站                |
| 2026-10-14 | 器材主清單用「器材類型」，不用品牌型號                                      | 推薦邏輯只關心能做什麼動作；不同分館可共用                                                          | 品牌型號清單                       |
| 2026-10-14 | 前端用 Quasar（Vue 3 + TypeScript），PWA 模式                               | 使用者熟悉 Vue / Quasar；行動優先元件、內建 PWA；之後可用 Capacitor 打包 App                        | React、Rust 前端（Leptos、Dioxus） |
| 2026-10-14 | 部署在 Cloudflare Workers，Hono 處理 `/api/*`，靜態檔由 Workers assets 提供 | 免費額度足夠、前後端同一個網域、合併到 `main` 自動部署                                              | GitHub Pages、Quasar SSR           |
| 2026-10-14 | local-first：IndexedDB 為主，D1 做備份與同步                                | 健身房收訊差也能用；換手機或清除資料時可還原                                                        | 只用 IndexedDB、只用 D1            |
| 2026-10-14 | 套件管理用 pnpm                                                             | 使用者同意                                                                                          | npm                                |
| 2026-10-27 | 前端維持 Quasar，不改 Rust                                                  | 推薦與重排的計算量很小（實測推薦 0.04 ms），改演算法比換語言有效；畫面元件與 PWA 支援 Quasar 較成熟 | Rust 前端                          |
| 2026-10-27 | 頁面拆成小組件與分層（pages → components → composables → utils / db）       | 使用者偏好小範圍 review；之後 D1 同步只改 `db/`                                                     | 大頁面元件                         |
| 2026-10-27 | Worker 的 JWT 驗證寫成通用版，由 `AUTH_*` 設定決定簽發者                    | 從 Cloudflare Access 換成自己的登入服務時只改設定                                                   | 寫死 Cloudflare Access             |
| 2026-10-27 | 登入改用自己的 `auth-service`，正式站不再用 Cloudflare Access               | 使用者不希望別人看出服務架在 Cloudflare 上（Access 的網址與 Google 同意畫面會露出）                 | Access + 自訂網域與 Instant Auth   |
| 2026-10-29 | 分支一律 `feature-<描述>`，從 `main` 開、PR 合併回來                        | 使用者指定的流程                                                                                    | `feat/`、`docs/`、`fix/` 等前綴    |
